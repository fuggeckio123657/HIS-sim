# 診所版（入門）與區網同步

登入畫面的「版本」可選 **診所版（入門・家醫科）** 或 大醫院版（完整）。兩版資料各自獨立保存。

## 診所版一天的流程
來客 → ① 櫃台掛號／讀健保卡（正常／忘帶卡／欠費／過期／自費）→ ② 護理量測 → ③ 診間（問診、理學檢查、自己寫 SOAP、開藥、開檢驗、完診）→ ④ 批價（診察費＋藥費＋藥事服務費＋部分負擔＋掛號費）→ ⑤ 藥局領藥（過敏審核、庫存、效期）→ ⑥ 外送檢驗報告 → ⑦ 日結 → ⑧ 月健保申報（檢核、送出、模擬審查、核減、申復）。
- **病人會自動上門**，並說出主訴；問診、理學檢查的回答在左欄，**S/O/A/P 一律由醫師（玩家）自己輸入**。
- **沒有做到一半的診**：按「完診」才一次寫入（失敗整批還原）；中途離開只保留本機草稿。
- **範本可擴充**：30 個家醫科內建範本（含慢性病、急性、衛教），可複製／編輯／新增／刪除／還原／匯入匯出 JSON；範本中的「＿」「（有/無）」必須由醫師改掉才能完診。
- SOAP 欄位：主訴、現病史、系統回顧、過去病史/過敏/用藥、家族史、社會史/TOCC、理學檢查、檢查結果、評估、計畫、衛教、追蹤。
- 診所帳號（密碼 1234）：C001 院長（全部權限，可一人包辦）、C002 醫師、C003 護理師、C004 櫃台／批價、C005 藥師。
- 預設已回放約兩個月營業：上上個月已申報核付、上個月待申報。

## 區網多裝置（需 Node.js 16+，無需安裝套件）
1. 把 `his.html` 與 `server.js` 放同一資料夾，執行 `node server.js`（可加埠號，預設 8080）。
2. 螢幕會列出區網網址，同網路的手機／平板／電腦用瀏覽器開啟該網址，選「診所版」登入即自動同步（狀態列顯示連線與在線台數）。
3. 各角色用不同裝置分工（護理師量測、櫃台批價、醫師看診、藥師領藥）。資料存於 `data/clinic.json`；設定視窗可重設。
- 直接雙擊 `his.html` 則為單機模式。
- 限制：規則在各瀏覽器內執行，伺服器只負責保存與轉送變更（輪詢約 1.2 秒）；**無登入驗證，請勿放上公開網路**；兩台同時建立新病人時病歷號可能重複（內部 ID 不會）。草稿只存在醫師自己的瀏覽器。
- 診所版暫以成人為主（病人 16 歲以上）；健保代碼、點數、規則皆為**虛構簡化**，與真實健保署規範無關。大醫院版範本仍為內建固定。
- 測試：`tests/`（test_flow、test_tx、test_clinic_seed、test_sync、persist_test、ui_test、ui_clinic_test；UI 測試需 jsdom）。

# 臺灣綜合醫學中心 HIS（原型版 v1.0.0）

高擬真台灣醫院資訊系統模擬器。**所有病人、員工、病歷皆為虛構**，僅供教育及娛樂用途。

## 啟動
- **最簡單**：直接用瀏覽器（Chrome/Edge/Firefox，建議 1366×768 以上）開啟 `his.html`。免安裝、免伺服器。
- 第一次開啟會自動產生虛構資料並存入瀏覽器 localStorage（約 1.4 MB），之後重新整理資料仍在。
- 修改原始碼後重新打包：`python3 build.py`（把 `src/` 合併成單一 `his.html`）。
- 重置資料：以管理者（ADM001）開「管理 → 系統工具 → 重置」。

## 建議的驗收路徑（同一位病人跨工作站）
1. D001 登入 →「門診候診清單」→ 開始看診 → 生命徵象 → 病歷(可套範本) → 診斷 → 醫囑（藥物/CBC/影像）→「簽署並送出醫囑」
2. 登出，PH001 登入 → 藥局：審核 → 調劑 → 發藥（庫存依效期先出扣除；可退藥）
3. LAB001 登入 → 檢驗：收件 → 輸入結果（異常自動標示、可改參考區間）→ 完成報告 → 發布
4. D001 登入 → 工作清單出現「未閱報告」→ 結果追蹤 → 檢閱 → 簽署病歷（可修訂，保留 v1/v2）→ 完成就診
5. ADM001 登入 → 操作紀錄 / 資料一致性檢查

## 架構
```
src/core.js      資料層 HIS.DB（all/get/where/insert/update + localStorage 持久化）
                 + 業務服務 HIS.svc（權限、CPOE、藥局、LIS、RIS、ADT、急診、稽核、一致性檢查）
src/seed.js      虛構資料與目錄（ICD-10-CM、藥品、檢驗項目、影像項目）
src/ui-*.js      傳統 MDI 介面：多視窗、選單、工具列、工作列、狀態列（與資料層無關）
tests/           服務層流程測試(node) 與 UI 驅動測試(jsdom)
```
- UI 只呼叫 `HIS.svc`；`HIS.svc` 只透過 `HIS.DB` 存取資料。**改接 FastAPI + PostgreSQL 只需替換 `HIS.DB` 實作**（目前同步 API，接 REST 時需改為 async，這是主要改動點）。
- 所有業務規則（狀態機、過敏攔截、簽署後不可覆寫、庫存、床位唯一性）都在 `HIS.svc`，不在畫面。
- 寫入類操作皆寫入 `audit_logs`（登入、檢視病人/病歷、建立、簽署、送出、調劑、發藥、退藥、收檢體、發布、危急值、修訂…）。

## 已知限制
- 資料存在瀏覽器 localStorage（通常上限約 5 MB）：長時間遊玩資料量大後需改接後端。
- 「系統管理員」擁有全部權限（含臨床功能），僅為方便測試。
- 介面行為已用 jsdom 自動化驗證（47 項點擊測試）；尚未在真實瀏覽器逐頁目視檢查版面，細部 CSS 可能需要微調。
